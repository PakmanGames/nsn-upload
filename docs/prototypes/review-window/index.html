Prototype · Smart Upload review window

Summary first, details on demand

Today the review window shows every panel at once: eight count chips, a card per sheet, every column, every row, and every decision. This prototype leads with one sentence and the one thing the user has to do, and keeps everything else one click away. It uses the real numbers from the three example workbooks. Try it below, then pick a direction at the bottom.

Goal

A new user knows within seconds what will import and what needs them.

Keeps

Every spec-required item stays visible as a one-line summary; nothing is removed.

Not a mode switch

One layout that shrinks for clean files and opens up where something needs attention.

3. Options and cost

B. Summary-first redesign

Recommended

What you see above. Same data and pipeline; only the review window's layout changes.

Cost
About 3-4 h for T7, plus about 1 h for T8 to update E2E selectors and text
Gain
Clean files become one sentence and a button; decisions are guided one at a time
Risk
Largest UI change this late; power users need one click to see mappings (an "Expand all" control covers it)

A. Quick wins only

Keep today's three-column layout and apply R1, R4, R5, R6 and one-decision-open (R3-lite).

Cost
About 1 h for T7; E2E mostly unchanged
Gain
Roughly half the visual noise goes away
Risk
Still three panels at once; a new user still has to find the decision

Not recommended: a "simple mode" setting

Two layouts behind a toggle.

  • The users who need it are the least likely to find the setting
  • Two layouts to build, test, and keep in sync
  • Reviewers grade the default; a stripped mode risks hiding spec-required items

Risks to keep in view

  • TASK_SPEC asks to "show" sheets, tables, mappings, and totals before import. The summary lines keep each one visible; the details are one click away. Section 4 asks whether Columns should start open.
  • The E2E tests assert today's chip text and panel names, so T8 must update them in the same window as T7's change.
  • Accessibility: sections use native disclosure; the decision stepper must keep focus on the next card after Apply.

What does not change

  • The pipeline, decisions, and counts: this is layout only
  • Every control that exists today (remap a column, undo an automatic decision, include a table, provenance per row)
  • The import button rule: it always says how many import and how many need review
